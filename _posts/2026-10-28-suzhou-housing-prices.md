我开源了一个面向 **苏州六区** 的住房成交数据分析小系统，仓库地址：[suzhou-housing-prices](https://github.com/wenyuhaokikika/suzhou-housing-prices)。

## 项目做什么

系统围绕 **实际成交价** 做汇总与可视化，而不是挂牌价或估算价。目标很朴素：把分散的成交信息整理成可查询、可对比的结构，方便看板块、面积段与时间趋势。

功能上主要包括：

- 按区域、小区、时间等维度检索成交记录
- 简单统计与图表展示（均价、成交量等）
- 轻量 Web 界面，便于本地或部署后演示

## 技术栈

| 层次 | 选择 | 说明 |
|------|------|------|
| API | [FastAPI](https://fastapi.tiangolo.com/) | 异步友好、OpenAPI 文档开箱即用 |
| 存储 | SQLite | 单机部署简单，适合分析型读多写少场景 |
| 前端 | 静态资源 + 模板/脚本 | 与 API 分离，便于 Pages 或 VPS 部署 |

数据库 schema 围绕 **成交事件** 设计：区域、小区、面积、总价、单价、成交日期等字段，便于后续扩展索引与聚合查询。

## 为什么仓库里是 Demo 数据

真实成交数据往往来自第三方站点，抓取容易触发 **反爬与访问限制**，也存在合规与稳定性问题。因此在公开仓库中：

- **默认附带的是脱敏/合成的 Demo 数据集**，用于跑通导入、API 与图表逻辑；
- 文档中说明了如何替换为你 **合法获得** 的数据源（例如自行整理的 CSV、合作方提供的导出等）。

这样别人 clone 后立刻能 `uvicorn` 跑起来，而不依赖我无法公开分发的原始抓取结果。

## 本地快速体验

克隆仓库后，按 README 安装依赖、初始化 SQLite、启动 FastAPI 即可。核心思路是：**导入脚本 → SQLite → REST API → 前端调用**。
